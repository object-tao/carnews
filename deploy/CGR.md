# 口岸动态与每日采集

前台入口 `/news/border-updates/`；日报沿用文章地址、SEO 元数据、结构化数据与 sitemap。报告日期以北京时间为准，发布时间保留首次发布的真实时间。国家筛选是哈萨克斯坦对接的国家或地区，库里克港归入里海方向。

展示范围：已发布且校验通过的哈萨克斯坦日报公开逐口岸预约日历、逐日期各档位名额与分页清单，可按国家、口岸、预约日期和名称筛选。数字直接展示，无需悬停。草稿和未到发布时间的报告不公开；下载仍仅后台授权用户可用。霍尔果斯车辆报告继续只公开汇总，业务编号、企业及逐条记录仅后台查询。

## 数据口径

- 唯一来源为 `https://cgr.qoldau.kz/ru/information/stat` 的预约区块；首次核对 51 个节点，6 个方向。`seed_cgr` 初始化中文名称与俄文标识，不覆盖后台修改。
- 完整读取源站实际日历范围，不固定截取 30 天。年月日根据预约区块更新时间、连续日期和日历边界共同校验，支持跨年。
- 剩余名额、休息日和尚未开放预约分别保存。色阶 6 是源站休息日，不是“极空闲”。色阶 0 是尚未开放。预约名额不用于推算现场排队或通关时长。
- 保留所有源站 МРП 档位。明确的零以数字 0 保存；休息日与未开放日没有名额字段，不补零。
- 源站未明确标注更新时间的时区，因此原样展示。北京时间报告日与源站预约日可以相差一天。
- 节点缺失、国家变化、异常日期/名额/状态、新增未审核节点，均阻止当次发布。新发现节点禁用并标为待核对，管理员确认归属及名称后可纳入。

## 后台操作

后台“口岸动态与自动采集”下提供：

1. **采集任务设置**：初始每天北京时间 03:10，启用定时与自动发布。可改时间或暂停。选中设置行，执行“立即补采一次”，请求通常一分钟内执行；手动补采在自动任务暂停时仍可使用。
2. **口岸与国家映射**：编辑中文名、国家、启停状态，关联现有口岸介绍。源站俄文名用于准确匹配；新增节点需核对后取消“待核对”。
3. **采集运行日志**：查看每次成功/失败、时间、记录数、摘要和原始页面哈希；异常详情仅在服务器日志。
4. **口岸预约明细**：按国家、日期、状态查询历史快照。
5. **口岸日报**：管理员预览及下载，发布草稿，或“撤回并暂停自动发布”。同日报重复补采更新数据版本，不重复建文章；已人工撤回的日报不会自动重新发布。

CSV、Excel、HTML 下载全部仅供具有日报和明细查看权限的后台员工使用（即使文章已公开），并设为禁止缓存与索引；旧公开下载地址对匿名用户返回 404。导出应用页面当前国家、口岸、关键词与日期筛选。未公开文件不放入公开媒体目录。Excel 的名额是数值，休息日为空；文本禁止被识别为公式。

## 服务器定时任务

源站连接启用标准 HTTPS 证书验证，单次最多重试三次。数据库租约保证同一时间一个采集；OS 终止进程后租约 15 分钟到期。每日失败可间隔至少 10 分钟再尝试，最多 3 次任务；管理员可手动补采。失败保留已有有效日报，前台保留实际采集时间，后台记录失败原因。

以 root 安装已审阅的 unit（只修改本应用）：

```bash
install -m 0644 /opt/kunteng-truck/current/deploy/kunteng-truck-cgr.service /etc/systemd/system/kunteng-truck-cgr.service
install -m 0644 /opt/kunteng-truck/current/deploy/kunteng-truck-cgr.timer /etc/systemd/system/kunteng-truck-cgr.timer
systemctl daemon-reload
systemctl enable --now kunteng-truck-cgr.timer
```

timer 每分钟检查一次，实际采集时刻从数据库读取，因此后台改时间无需改系统服务。首次启用时若当天已过设定时间，会补执行当天任务；不会伪造停机期间的历史数据。服务以 `kunteng-web` 运行，只允许写本应用共享数据目录。

```bash
systemctl list-timers kunteng-truck-cgr.timer
journalctl -u kunteng-truck-cgr.service -n 30 --no-pager
```

原始页面压缩存于 `shared/data/cgr/raw/`；规范化快照、任务和日报关联存于 SQLite。`deploy/backup.py` 已把原始归档加入备份；安装时同步到 `/usr/local/lib/kunteng-backup.py`。每次发布先运行原有一致性备份，再迁移与 `seed_cgr`。升级发布后 timer 通过 `current` 使用新代码，无需重装 unit（除非 unit 本身更改）。

## 验证

`python manage.py test` 覆盖解析、跨年、全部档位、休息日、缺失节点、异常数值、国家映射、新口岸隔离、重复采集、发布事务、撤回权限、CSV/Excel/HTML 安全及北京时间调度。实时源站可通过 `python manage.py collect_cgr` 验证；此命令会生成并按后台配置发布当日日报。
