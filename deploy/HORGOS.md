# 霍尔果斯车辆采集与口岸汇总发布

## 运行和口径

- 来源为用户提供的 `Desktop/11/holgos_client.py` 的五个数据接口，标准 TLS 校验；没有复制原程序关闭证书校验、失败补零的行为。无需新增第三方依赖。
- 北京时间每天 **23:50**，与 CGR 的 **03:10** 各自独立。systemd 每分钟轮询数据库中的时间；后台可改时间、关闭自动发布或立即补采。
- 每次重新请求全部五个接口，不以历史缓存补齐失败字段。只有同日、五分钟内完成且字段完整的一轮数据才可入库并发布。跨日、缺字段、冲突记录、非数值统计、异常日期均停止发布，保留此前有效文章。
- 明细只纳入本轮取得的北京时间当日业务记录。源接口每类只提供最近 1000 条，无已验证的分页功能；每天一次无法保证收齐全天明细。日报采用独立汇总接口，不用明细数量推算总数。源站汇总没有业务日期字段，文章明确标注本轮采集日期、起止时间与“截至采集时点”，不声称全天最终统计。
- 不同接口由源站独立响应，没有事务快照接口。因此“同一轮”代表这一采集时间区间，而非严格同一毫秒。原响应仅保存于私有归档。

## 去重与版本

- 源站没有记录 ID，业务键为来源、类型、业务编号、业务时间；重复不再插入，企业/状态变化生成新版本。每轮关联确切的不可变版本，后台查看历史批次不会混入后续修正。
- 汇总按业务日及全部统计值去重；原始 JSON 按内容哈希归档。
- 每个来源、每天仅一篇文章；重跑更新同一文章并保留首次发布时间。人工撤回可阻止后续自动重新发布。
- CGR 预约单元按口岸、日期、状态、色阶及档位值去重，每轮通过关系表保留完整归属；迁移核对各轮数量，可反向恢复旧结构。

## 前后台

- `/news/border-updates/` 是汇总文章列表，可筛选国家、来源、报告日期及标题关键词。SEO、Article 结构化数据、sitemap 沿用文章系统。
- 霍尔果斯报告只公开汇总图表，车辆编号、企业、逐条明细和私有归档仅后台查询。哈萨克斯坦已发布日报恢复公开预约日历与逐口岸档位名额；CSV/XLSX/HTML 导出仍仅限后台授权用户，旧下载 URL 对匿名用户返回 404。两套来源的详情权限独立控制。
- 后台“霍尔果斯车辆采集”提供设置、日报、运行日志、车辆明细、明细变更版本与汇总版本。运行日志的“本轮明细”链接只查询该批次记录。
- 校验失败写运行日志，不发空报告；定时失败间隔至少两分钟重试，最多三轮，跨过零点不补造上一日报告。管理员可手动补采当前日期。

## 部署

先备份，暂停 CGR timer 并等待正在执行的任务结束，运行 `migrate` 和 `refresh_border_reports` 后切换应用。确认旧文章、各历史批次数据一致，再恢复 timer。

```bash
install -m 0644 /opt/kunteng-truck/current/deploy/kunteng-truck-horgos.service /etc/systemd/system/kunteng-truck-horgos.service
install -m 0644 /opt/kunteng-truck/current/deploy/kunteng-truck-horgos.timer /etc/systemd/system/kunteng-truck-horgos.timer
systemctl daemon-reload
systemctl enable --now kunteng-truck-horgos.timer
systemctl start kunteng-truck-cgr.timer
```

私有归档在 `shared/data/cgr/horgos/raw/`，已被原有备份程序的 `cgr` 目录备份覆盖。新 timer 使用 `current` 发布路径，以 `kunteng-web` 低权限运行，写入仅限共享数据目录。不能在服务日志打印原始企业及编号。

上线验收可临时关闭霍尔果斯自动发布后执行 `python manage.py collect_horgos`，验证真实数据为草稿，再恢复自动发布；23:50 定时任务重新请求数据并发布当天文章。
